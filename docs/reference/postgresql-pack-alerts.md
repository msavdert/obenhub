# PostgreSQL pack alerts

Generated by `scripts/gen-pack-alerts.py` from `packs/postgresql/rules.yml`; do not edit. Each alert is a heading named as the alert, so its anchor is the lowercased name. An alert with two severities has one entry per tier.

## PostgresTargetAbsent

An expected PostgreSQL target has sent no heartbeat (postgresql.collection.heartbeat) for 2 minutes while its Collector is alive. Check that PostgreSQL runs and that the monitoring role can connect.

**critical**, for 1m

```text
obenhub.expected_target{service.name="postgresql"}
  unless on(obenhub.cluster.name, service.instance.id)
present_over_time(postgresql.collection.heartbeat[2m])
  and on(obenhub.collector)
label_replace(present_over_time(otelcol_process_uptime[1m]), "obenhub.collector", "$1", "service.instance.id", "(.+)")
```

## PostgresClusterNameMissing

A PostgreSQL target carries no obenhub.cluster.name, so every join of the pack pairs it with nothing and PostgresTargetAbsent fires against its inventory entry. Fix the resource attribute of the Collector.

**warning**, for 5m

```text
postgresql.collection.heartbeat{obenhub.cluster.name=""}
```

## PostgresCollectionIntervalTooLong

The target is collected less often than every 15 s (average spacing above 20 s over 5 minutes), while the rules size their windows for 15 s, so they go quiet or flap. Set the collection interval back to 15 s.

**warning**, for 10m

```text
max by (obenhub.cluster.name, service.instance.id) (scrape_interval(postgresql.collection.heartbeat[5m])) > 20
```

## PostgresStandbyNotStreaming

A standby is in recovery with no WAL receiver streaming for a minute, while another member of the cluster is writable. Query pg_stat_wal_receiver on the standby and pg_stat_replication on the primary.

**critical**, for 1m

```text
postgresql.wal_receiver.streaming == 0
  and on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
postgresql.recovery.active == 1
  and on(obenhub.cluster.name)
count by (obenhub.cluster.name) (postgresql.recovery.active == 0) > 0
```

## PostgresSnapshotHeldTooLong

**warning**, for 30s

```text
postgresql.snapshot.oldest_age > 120
```

## PostgresXminHorizonHeld

The xmin horizon is more than 10 million transactions old for 5 minutes with no client snapshot over 120 s to explain it, so something else pins old row versions. Check pg_replication_slots (xmin, catalog_xmin), pg_stat_replication (backend_xmin) and pg_prepared_xacts.

**warning**, for 5m

```text
postgresql.xmin_horizon.age > 10000000
  unless on(obenhub.cluster.name, service.instance.id)
postgresql.snapshot.oldest_age > 120
```

## PostgresConnectionSaturation

Client connections are above 85 % of the connection limit (critical at 95 %), as the lowest value over the last 75 seconds. Count sessions in pg_stat_activity by state and application to find who holds them.

**warning**, no hold time

```text
WITH (
  r = postgresql.client_connection.count
    / on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
  postgresql.client_connection.limit,
  x = min_over_time(r[75s:15s]),
  n = count_over_time(r[75s:15s])
)
((x > 0.85) unless (x >= 0.95)) and (n >= 5)
```

**critical**, no hold time

```text
WITH (
  r = postgresql.client_connection.count
    / on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
  postgresql.client_connection.limit,
  x = min_over_time(r[75s:15s]),
  n = count_over_time(r[75s:15s])
)
(x >= 0.95) and (n >= 5)
```

## PostgresTransactionIdWraparound

The age of a database's datfrozenxid (kind xid) or datminmxid (kind mxid) is above 50 % of the wraparound limit 2^31 (critical above 75 %). Check pg_database for the database and whether autovacuum freezing can progress.

**warning**, no hold time

```text
WITH (
  f = label_set(postgresql.database.xid_age / 2147483648, "kind", "xid")
    or
  label_set(postgresql.database.mxid_age / 2147483648, "kind", "mxid"),
  x = min_over_time(f[315s:15s]),
  n = count_over_time(f[315s:15s])
)
(((x > 0.5) unless (x > 0.75)) and (n >= 21))
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

**critical**, no hold time

```text
WITH (
  f = label_set(postgresql.database.xid_age / 2147483648, "kind", "xid")
    or
  label_set(postgresql.database.mxid_age / 2147483648, "kind", "mxid"),
  x = min_over_time(f[315s:15s]),
  n = count_over_time(f[315s:15s])
)
((x > 0.75) and (n >= 21))
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresIdleInTransaction

A session has been idle in a transaction for more than 60 seconds (critical over 180 s; lab thresholds). Find it in pg_stat_activity where state is idle in transaction, ordered by state_change.

**warning**, no hold time

```text
WITH (
  x = min_over_time(postgresql.transaction.idle_age[45s:15s]),
  n = count_over_time(postgresql.transaction.idle_age[45s:15s])
)
((x > 60) unless (x > 180)) and (n >= 3)
```

**critical**, no hold time

```text
WITH (
  x = min_over_time(postgresql.transaction.idle_age[45s:15s]),
  n = count_over_time(postgresql.transaction.idle_age[45s:15s])
)
(x > 180) and (n >= 3)
```

## PostgresBlockedSessions

A session has waited more than 30 seconds for a lock (lab threshold). Join pg_locks with pg_stat_activity or call pg_blocking_pids() to find the blocker.

**warning**, for 30s

```text
postgresql.lock.oldest_wait_age > 30
```

## PostgresDeadlocks

The deadlock counter of a database rose within the last 5 minutes. PostgreSQL resolves a deadlock by aborting one session, so this is evidence, not an outage; check the PostgreSQL log.

**warning**, no hold time

```text
last_over_time(postgresql.deadlocks[5m]) - first_over_time(postgresql.deadlocks[5m]) > 0
```

## PostgresCheckpointsRequested

More than 3 requested checkpoints in 5 minutes on a primary: WAL reached max_wal_size before checkpoint_timeout (lab threshold). Check max_wal_size against the WAL volume and what writes it.

**warning**, for 1m

```text
(
  last_over_time(postgresql.bgwriter.checkpoint.count{type="requested"}[5m])
    - first_over_time(postgresql.bgwriter.checkpoint.count{type="requested"}[5m])
) > 3
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresReplicationSlotRetainingWAL

A valid slot on a primary holds back more than 512 MiB of WAL for 2 minutes (lab threshold), so the volume is filling. Check pg_replication_slots (retained WAL, active) and bring the consumer back or drop the slot.

**warning**, for 2m

```text
(
  postgresql.replication_slot.retained_wal > 512 * 1024 * 1024
    unless on(obenhub.cluster.name, service.instance.id, postgresql.replication_slot.name)

  and on(obenhub.cluster.name, service.instance.id)
```


## PostgresMultiplePrimaries

Two or more instances of one cluster are writable (postgresql.recovery.active 0) at the same time for 60 seconds: split brain, independent of any cluster manager. Check pg_is_in_recovery() on every member and stop one.

**critical**, for 60s

```text
count by (obenhub.cluster.name, k8s.namespace.name) (
  max by (obenhub.cluster.name, k8s.namespace.name, service.instance.id) (
    last_over_time(postgresql.recovery.active[30s])
  ) == 0
) > 1
```

## PostgresLogicalApplyErrors

A logical subscription raised its apply or sync error counter by 2 or more within 3 minutes: the apply worker keeps failing on a change. Check pg_stat_subscription_stats and the subscriber's PostgreSQL log for the conflicting row.

**critical**, no hold time

```text
(last_over_time(postgresql.subscription.apply_error[3m]) - first_over_time(postgresql.subscription.apply_error[3m]))
  + (last_over_time(postgresql.subscription.sync_error[3m]) - first_over_time(postgresql.subscription.sync_error[3m])) >= 2
```

## PostgresLogicalSubscriptionNotStreaming

An enabled subscription has had no apply worker for most of a minute, or no message for over 60 seconds, without errors that PostgresLogicalApplyErrors would own. Check pg_stat_subscription on the subscriber and the connection to the publisher.

**critical**, for 1m

```text
(
  postgresql.subscription.enabled == 1
    and on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
  (
    avg_over_time(postgresql.subscription.apply_worker_running[1m]) < 0.5
      or on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
    postgresql.subscription.last_msg_age > 60
  )
)
  unless on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
(
  (last_over_time(postgresql.subscription.apply_error[3m]) - first_over_time(postgresql.subscription.apply_error[3m]))
    + on(obenhub.cluster.name, service.instance.id, k8s.pod.uid, postgresql.subscription.name)
  (last_over_time(postgresql.subscription.sync_error[3m]) - first_over_time(postgresql.subscription.sync_error[3m])) >= 2
)
  and on(obenhub.cluster.name, service.instance.id)
present_over_time(postgresql.collection.heartbeat[2m])
```

## PostgresLogicalSlotStalled

A logical slot on the publisher has been inactive for over 180 seconds, or has more than 128 MiB of WAL unconfirmed, for a minute. Check pg_replication_slots and the state of the subscriber that reads it.

**warning**, for 1m

```text
(
  postgresql.replication_slot.inactive_age{postgresql.replication_slot.type="logical"} > 180
    or on(obenhub.cluster.name, service.instance.id, postgresql.replication_slot.name)
  postgresql.replication_slot.unconfirmed_wal{postgresql.replication_slot.type="logical"} > 128 * 1024 * 1024
)
```
