# PostgreSQL pack alerts

Generated by `scripts/gen-pack-alerts.py` from `packs/postgresql/rules.yml`; do not edit. Each alert is a heading named as the alert, so its anchor is the lowercased name. An alert with two severities has one entry per tier.

## Thresholds

Each row is a limit a rule compares against: the default is in the rule, and a lab overrides it by recording the series (ADR 0006, lab parameters). A tiered alert reads one series with a `severity` label per tier. The selector is the label matcher of the series the rule reads.

## PostgresTargetAbsent

An expected PostgreSQL target has sent no heartbeat (postgresql.collection.heartbeat) for 2 minutes while its Collector is alive. Check that PostgreSQL runs and that the monitoring role can connect.

**critical**, for 1m

```text
obenhub.expected_target{service.name="postgresql"}
  unless on(obenhub.cluster.name, service.instance.id)
present_over_time(postgresql.collection.heartbeat[2m])
  and on(obenhub.collector)
label_replace(present_over_time(otelcol_process_uptime[1m]), "obenhub.collector", "$1", "service.instance.id", "(.+)")
```

## PostgresClusterNameMissing

A PostgreSQL target carries no obenhub.cluster.name, so every join of the pack pairs it with nothing and PostgresTargetAbsent fires against its inventory entry. Fix the resource attribute of the Collector.

**warning**, for 5m

```text
postgresql.collection.heartbeat{obenhub.cluster.name=""}
```

## PostgresCollectionIntervalTooLong

The target is collected less often than every 15 s (average spacing above 20 s over 5 minutes), while the rules size their windows for 15 s, so they go quiet or flap. Set the collection interval back to 15 s.

**warning**, for 10m

```text
max by (obenhub.cluster.name, service.instance.id) (scrape_interval(postgresql.collection.heartbeat[5m])) > 20
```

## PostgresStandbyNotStreaming

A standby is in recovery with no WAL receiver streaming for a minute, while another member of the cluster is writable. Query pg_stat_wal_receiver on the standby and pg_stat_replication on the primary.

**critical**, for 1m

```text
postgresql.wal_receiver.streaming == 0
  and on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
postgresql.recovery.active == 1
  and on(obenhub.cluster.name)
count by (obenhub.cluster.name) (postgresql.recovery.active == 0) > 0
```

## PostgresSynchronousStandbyMissing

The primary lists fewer synchronous standbys in pg_stat_replication than synchronous_standby_names requires, for a minute; commits wait for a standby. Check which standby dropped out of pg_stat_replication.

**critical**, for 1m

```text
postgresql.replication.synchronous_standby.count
  < on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
postgresql.replication.synchronous_standby.required
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresReplayBacklog

A standby has received more WAL than the limit (256 MiB unless the lab sets obenhub.postgresql.replay_backlog.limit) that it has not replayed, for a minute. Check pg_get_wal_replay_pause_state() on the standby.

**warning**, for 1m

```text
(
  postgresql.replay.backlog
    > on() group_left()
  (obenhub.postgresql.replay_backlog.limit or on() vector(268435456))
)
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 1
```

## PostgresSnapshotHeldTooLong

A snapshot on the instance is older than the limit (1800 s unless the lab sets obenhub.postgresql.snapshot_age.limit) for 30 seconds, which holds back the xmin horizon. Look for the oldest transaction in pg_stat_activity by xact_start and backend_xmin.

**warning**, for 30s

```text
postgresql.snapshot.oldest_age
  > on() group_left()
(obenhub.postgresql.snapshot_age.limit or on() vector(1800))
```

## PostgresXminHorizonHeld

The xmin horizon is older than the limit (50 million transactions unless the lab sets obenhub.postgresql.xmin_horizon_age.limit) for 5 minutes with no client snapshot over its limit (1800 s unless the lab sets obenhub.postgresql.snapshot_age.limit) to explain it, so something else pins old row versions. Check pg_replication_slots (xmin, catalog_xmin), pg_stat_replication (backend_xmin) and pg_prepared_xacts.

**warning**, for 5m

```text
postgresql.xmin_horizon.age
  > on() group_left()
(obenhub.postgresql.xmin_horizon_age.limit or on() vector(50000000))
  unless on(obenhub.cluster.name, service.instance.id)
postgresql.snapshot.oldest_age
  > on() group_left()
(obenhub.postgresql.snapshot_age.limit or on() vector(1800))
```

## PostgresConnectionSaturation

Client connections are above 85 % of the connection limit (critical at 95 %), unless the lab sets obenhub.postgresql.connection_saturation.limit per severity, as the lowest value over the last 75 seconds. Count sessions in pg_stat_activity by state and application to find who holds them.

**warning**, no hold time

```text
WITH (
  r = postgresql.client_connection.count
    / on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
  postgresql.client_connection.limit,
  x = min_over_time(r[75s:15s]),
  n = count_over_time(r[75s:15s])
)
(
  (x > on() group_left() (obenhub.postgresql.connection_saturation.limit{severity="warning"} or on() vector(0.85)))
    unless
  (x >= on() group_left() (obenhub.postgresql.connection_saturation.limit{severity="critical"} or on() vector(0.95)))
)
  and (n >= 5)
```

**critical**, no hold time

```text
WITH (
  r = postgresql.client_connection.count
    / on(obenhub.cluster.name, service.instance.id, k8s.pod.uid)
  postgresql.client_connection.limit,
  x = min_over_time(r[75s:15s]),
  n = count_over_time(r[75s:15s])
)
(x >= on() group_left() (obenhub.postgresql.connection_saturation.limit{severity="critical"} or on() vector(0.95)))
  and (n >= 5)
```

## PostgresTransactionIdWraparound

The age of a database's datfrozenxid (kind xid) or datminmxid (kind mxid) is above 50 % of the wraparound limit 2^31 (critical above 75 %), unless the lab sets obenhub.postgresql.wraparound_ratio.limit per severity. Check pg_database for the database and whether autovacuum freezing can progress.

**warning**, no hold time

```text
WITH (
  f = label_set(postgresql.database.xid_age / 2147483648, "kind", "xid")
    or
  label_set(postgresql.database.mxid_age / 2147483648, "kind", "mxid"),
  x = min_over_time(f[315s:15s]),
  n = count_over_time(f[315s:15s])
)
(
  (x > on() group_left() (obenhub.postgresql.wraparound_ratio.limit{severity="warning"} or on() vector(0.5)))
    unless
  (x > on() group_left() (obenhub.postgresql.wraparound_ratio.limit{severity="critical"} or on() vector(0.75)))
)
  and (n >= 21)
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

**critical**, no hold time

```text
WITH (
  f = label_set(postgresql.database.xid_age / 2147483648, "kind", "xid")
    or
  label_set(postgresql.database.mxid_age / 2147483648, "kind", "mxid"),
  x = min_over_time(f[315s:15s]),
  n = count_over_time(f[315s:15s])
)
(x > on() group_left() (obenhub.postgresql.wraparound_ratio.limit{severity="critical"} or on() vector(0.75)))
  and (n >= 21)
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresIdleInTransaction

A session has been idle in a transaction for more than 300 seconds (critical over 1800 s) unless the lab sets obenhub.postgresql.idle_in_transaction_age.limit per severity. Find it in pg_stat_activity where state is idle in transaction, ordered by state_change.

**warning**, no hold time

```text
WITH (
  x = min_over_time(postgresql.transaction.idle_age[45s:15s]),
  n = count_over_time(postgresql.transaction.idle_age[45s:15s])
)
(
  (x > on() group_left() (obenhub.postgresql.idle_in_transaction_age.limit{severity="warning"} or on() vector(300)))
    unless
  (x > on() group_left() (obenhub.postgresql.idle_in_transaction_age.limit{severity="critical"} or on() vector(1800)))
)
  and (n >= 3)
```

**critical**, no hold time

```text
WITH (
  x = min_over_time(postgresql.transaction.idle_age[45s:15s]),
  n = count_over_time(postgresql.transaction.idle_age[45s:15s])
)
(x > on() group_left() (obenhub.postgresql.idle_in_transaction_age.limit{severity="critical"} or on() vector(1800)))
  and (n >= 3)
```

## PostgresBlockedSessions

A session has waited more than the limit (120 s unless the lab sets obenhub.postgresql.lock_wait_age.limit) for a lock. Join pg_locks with pg_stat_activity or call pg_blocking_pids() to find the blocker.

**warning**, for 30s

```text
postgresql.lock.oldest_wait_age
  > on() group_left()
(obenhub.postgresql.lock_wait_age.limit or on() vector(120))
```

## PostgresDeadlocks

The deadlock counter of a database rose within the last 5 minutes. PostgreSQL resolves a deadlock by aborting one session, so this is evidence, not an outage; pg_stat_database.deadlocks shows which database and the PostgreSQL log has the details.

**warning**, no hold time

```text
last_over_time(postgresql.deadlocks[5m]) - first_over_time(postgresql.deadlocks[5m]) > 0
```

## PostgresStatementsEvicted

More distinct statements arrived than pg_stat_statements.max holds, so the least used entries were evicted and the statement totals of the pack (execution time, calls, temp blocks written per database) undercount. Raise pg_stat_statements.max (needs a restart) or find the source of the distinct statements (unparameterised literals, generated SQL).

**warning**, no hold time

```text
last_over_time(postgresql.statement.deallocation[5m]) - first_over_time(postgresql.statement.deallocation[5m]) > 0
```

## PostgresCheckpointsRequested

More than 3 requested checkpoints in 5 minutes on a primary (3 unless the lab sets obenhub.postgresql.requested_checkpoints.limit). Usually WAL reached max_wal_size before checkpoint_timeout, but CHECKPOINT, CREATE DATABASE, base backups, promotion and shutdown also request one. Check pg_stat_checkpointer, max_wal_size against the WAL volume and what writes it.

**warning**, for 1m

```text
(
  last_over_time(postgresql.bgwriter.checkpoint.count{type="requested"}[5m])
    - first_over_time(postgresql.bgwriter.checkpoint.count{type="requested"}[5m])
)
  > on() group_left()
(obenhub.postgresql.requested_checkpoints.limit or on() vector(3))
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresPhysicalSlotInactive

A physical replication slot on the primary has had no consumer for more than the limit (900 s unless the lab sets obenhub.postgresql.physical_slot_inactive_age.limit) and is not invalidated, so it keeps WAL. Check pg_replication_slots and whether its standby is still connected.

**warning**, for 1m

```text
(
  postgresql.replication_slot.inactive_age{postgresql.replication_slot.type="physical"}
    > on() group_left()
  (obenhub.postgresql.physical_slot_inactive_age.limit or on() vector(900))
    unless on(obenhub.cluster.name, service.instance.id, postgresql.replication_slot.name)
  postgresql.replication_slot.invalidated == 1
)
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

## PostgresReplicationSlotInvalidated

A replication slot is invalidated for 30 seconds; the invalidation reason is in the alert. The slot no longer retains WAL. Check pg_replication_slots (wal_status, invalidation_reason) and the consumer that depended on it.

**critical**, for 30s

```text
postgresql.replication_slot.invalidated == 1
```

## PostgresReplicationSlotRetainingWAL

A valid slot on a primary holds back more than the limit of WAL (8 GiB unless the lab sets obenhub.postgresql.slot_retained_wal.limit) for 2 minutes, so the volume is filling. Check pg_replication_slots (retained WAL, active) and bring the consumer back or drop the slot.

**warning**, for 2m

```text
(
  postgresql.replication_slot.retained_wal
    > on() group_left()
  (obenhub.postgresql.slot_retained_wal.limit or on() vector(8589934592))
    unless on(obenhub.cluster.name, service.instance.id, postgresql.replication_slot.name)
  postgresql.replication_slot.invalidated == 1
)
  and on(obenhub.cluster.name, service.instance.id)
postgresql.recovery.active == 0
```

**warning**, for 1m

```text
postgresql.archiver.failing == 1
```

**warning**, for 2m

```text
postgresql.archiver.ready_file.count
  > on() group_left()
```


## PostgresMultiplePrimaries

Two or more instances of one cluster are writable (postgresql.recovery.active 0) at the same time for 60 seconds: split brain, independent of any cluster manager. Check pg_is_in_recovery() on every member and stop one.

**critical**, for 60s

```text
count by (obenhub.cluster.name, k8s.namespace.name) (
  max by (obenhub.cluster.name, k8s.namespace.name, service.instance.id) (
    last_over_time(postgresql.recovery.active[30s])
  ) == 0
) > 1
```

## PostgresLogicalApplyErrors

A logical subscription raised its apply or sync error counter by 2 or more (unless the lab sets obenhub.postgresql.apply_errors.limit) within 3 minutes: the apply worker keeps failing on a change. Check pg_stat_subscription_stats and the subscriber's PostgreSQL log for the conflicting row.

**critical**, no hold time

```text
(
  (last_over_time(postgresql.subscription.apply_error[3m]) - first_over_time(postgresql.subscription.apply_error[3m]))
    + (last_over_time(postgresql.subscription.sync_error[3m]) - first_over_time(postgresql.subscription.sync_error[3m]))
)
  >= on() group_left()
(obenhub.postgresql.apply_errors.limit or on() vector(2))
```

## PostgresLogicalSubscriptionNotStreaming

An enabled subscription has had no apply worker for most of a minute, or no message for over the limit (300 s unless the lab sets obenhub.postgresql.subscription_msg_age.limit), without errors that PostgresLogicalApplyErrors would own. Check pg_stat_subscription on the subscriber and the connection to the publisher.

**critical**, for 1m

```text
(
  postgresql.subscription.enabled == 1
    and on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
  (
    avg_over_time(postgresql.subscription.apply_worker_running[1m]) < 0.5
      or on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
    postgresql.subscription.last_msg_age
      > on() group_left()
    (obenhub.postgresql.subscription_msg_age.limit or on() vector(300))
  )
)
  unless on(obenhub.cluster.name, service.instance.id, postgresql.subscription.name)
(
  (
    (last_over_time(postgresql.subscription.apply_error[3m]) - first_over_time(postgresql.subscription.apply_error[3m]))
      + on(obenhub.cluster.name, service.instance.id, k8s.pod.uid, postgresql.subscription.name)
    (last_over_time(postgresql.subscription.sync_error[3m]) - first_over_time(postgresql.subscription.sync_error[3m]))
  )
    >= on() group_left()
  (obenhub.postgresql.apply_errors.limit or on() vector(2))
)
  and on(obenhub.cluster.name, service.instance.id)
present_over_time(postgresql.collection.heartbeat[2m])
```

Check pg_replication_slots and the state of the subscriber that reads it.

**warning**, for 1m

```text
(
  postgresql.replication_slot.inactive_age{postgresql.replication_slot.type="logical"}
    > on() group_left()
  (obenhub.postgresql.logical_slot_inactive_age.limit or on() vector(900))
    or on(obenhub.cluster.name, service.instance.id, postgresql.replication_slot.name)
  postgresql.replication_slot.unconfirmed_wal{postgresql.replication_slot.type="logical"}
    > on() group_left()
  (obenhub.postgresql.logical_slot_unconfirmed_wal.limit or on() vector(4294967296))
)
```
