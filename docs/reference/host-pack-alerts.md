# Host pack alerts

Generated by `scripts/gen-pack-alerts.py` from `packs/host/rules.yml`; do not edit. Each alert is a heading named as the alert, so its anchor is the lowercased name. An alert with two severities has one entry per tier.

## Thresholds

Each row is a limit a rule compares against: the default is in the rule, and a lab overrides it by recording the series (ADR 0006, lab parameters). A tiered alert reads one series with a `severity` label per tier. The selector is the label matcher of the series the rule reads.

| Alert | Series | Selector | Default | Unit | Fires when the value is |
| --- | --- | --- | --- | --- | --- |
| HostFilesystemSpaceLow | `obenhub.host.filesystem_free_ratio.limit` |  | 0.1 | `1` | below the limit |
| HostMemoryAvailableLow | `obenhub.host.memory_available_ratio.limit` |  | 0.1 | `1` | below the limit |
| HostDiskIOSaturation | `obenhub.host.disk_queue_depth.limit` |  | 10 | `{request}` | above the limit |

## HostFilesystemSpaceLow

Under 10 % of a mounted ext4, xfs or btrfs filesystem is free for 2 minutes (system.filesystem.usage; 10 % unless the lab sets obenhub.host.filesystem_free_ratio.limit). Find what grows under the mount point named in the alert, for a PostgreSQL host start with the data and WAL directories.

**warning**, for 2m

```text
sum by (host.name, service.instance.id, mountpoint) (system.filesystem.usage{state="free", type=~"ext4|xfs|btrfs"})
  /
sum by (host.name, service.instance.id, mountpoint) (system.filesystem.usage{state=~"free|used", type=~"ext4|xfs|btrfs"})
  < on() group_left()
(obenhub.host.filesystem_free_ratio.limit or on() vector(0.1))
```

## HostMemoryAvailableLow

MemAvailable (system.linux.memory.available) is under 10 % of the host's memory for 2 minutes (10 % unless the lab sets obenhub.host.memory_available_ratio.limit). Read MemAvailable and MemTotal in /proc/meminfo, then look for the process that grew.

**warning**, for 2m

```text
sum by (host.name, service.instance.id) (system.linux.memory.available)
  /
sum by (host.name, service.instance.id) (system.memory.limit)
  < on() group_left()
(obenhub.host.memory_available_ratio.limit or on() vector(0.1))
```

## HostDiskIOSaturation

A whole disk had more than 10 requests in flight on average for 30 minutes (rate of system.disk.weighted_io_time over 5 minutes, iostat's aqu-sz; 10 unless the lab sets obenhub.host.disk_queue_depth.limit). Requests queue faster than the disk completes them, so each one waits longer: find the process doing the I/O, then compare the disk's throughput with what it can deliver.

**warning**, for 30m

```text
sum by (host.name, service.instance.id, device) (rate(system.disk.weighted_io_time{device=~"sd[a-z]+|vd[a-z]+|xvd[a-z]+|hd[a-z]+|nvme[0-9]+n[0-9]+|mmcblk[0-9]+"}[5m]))
  > on() group_left()
(obenhub.host.disk_queue_depth.limit or on() vector(10))
```

## HostRebooted

system.uptime of the host is under 5 minutes: it booted just now, whatever the reason (watchdog, power, operator). Check the host's boot log for the cause and the services that did not come back.

**warning**, no hold time

```text
min by (host.name, service.instance.id) (system.uptime) < 300
```
