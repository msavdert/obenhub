# Oracle Data Guard pack alerts

Generated by `scripts/gen-pack-alerts.py` from `packs/oracledb-dg/rules.yml`; do not edit. Each alert is a heading named as the alert, so its anchor is the lowercased name. An alert with two severities has one entry per tier.

## OracleClusterNameMissing

The database's heartbeat series carries no obenhub.cluster.name, so the role and Data Guard rules cannot group it. Fix the resource attribute of the Collector.

**warning**, for 5m

```text
oracledb.collection.heartbeat{obenhub.cluster.name=""}
```

## OracleCollectionIntervalTooLong

The database is collected less often than every 15 s (average spacing above 20 s over 5 minutes), while the rules size their windows for 15 s, so they go quiet or flap. Set the collection interval of the oracledb receiver back to 15 s.

**warning**, for 10m

```text
max by (obenhub.cluster.name, service.instance.id) (scrape_interval(oracledb.collection.heartbeat[5m])) > 20
```

## OracleTargetAbsent

An expected Oracle target has sent no heartbeat for 2 minutes while its Collector is alive. Check that the database is up and that the monitoring account can connect.

**critical**, for 1m

```text
obenhub.expected_target{service.name="oracledb"}
  unless on(obenhub.cluster.name, service.instance.id)
present_over_time(oracledb.collection.heartbeat[2m])
  and on(obenhub.collector)
label_replace(present_over_time(otelcol_process_uptime[1m]), "obenhub.collector", "$1", "service.instance.id", "(.+)")
```

## OraclePrimaryChanged

A database reports PRIMARY after having reported another role within the last 3 minutes: a standby was promoted, by switchover or failover (the signal cannot tell them apart). Check the Data Guard broker configuration and its log.

**warning**, no hold time

```text
max by (obenhub.cluster.name) (
  (
    max by (service.instance.id, obenhub.cluster.name) (
      tlast_over_time(oracledb.database.primary[3m]) and (last_over_time(oracledb.database.primary[3m]) == 1)
    )
      > on(service.instance.id, obenhub.cluster.name)
    max by (service.instance.id, obenhub.cluster.name) (
      tlast_over_time(oracledb.database.primary[3m]) and (last_over_time(oracledb.database.primary[3m]) == 0)
    )
  )
    and on(service.instance.id, obenhub.cluster.name)
  (max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.primary[1m])) == 1)
)
```

## OracleMultiplePrimaries

More than one database of one cluster is PRIMARY and open at the same time for a minute: split brain. Check which database the broker considers primary and stop the other.

**critical**, for 1m

```text
count by (obenhub.cluster.name) (
  (max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.primary[1m])) == 1)
    and on(service.instance.id, obenhub.cluster.name)
  (max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.open[1m])) == 1)
) > 1
```

## OracleNoPrimary

At least one database of the cluster reports, but none is PRIMARY and open, for a minute: a failover not completed or a primary lost. Check the broker status and the state of both databases.

**critical**, for 1m

```text
max by (obenhub.cluster.name) (present_over_time(oracledb.collection.heartbeat[1m]))
  unless on(obenhub.cluster.name)
max by (obenhub.cluster.name) (
  (max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.primary[1m])) == 1)
    and on(service.instance.id, obenhub.cluster.name)
  (max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.open[1m])) == 1)
)
```

## OracleProtectionDegraded

The primary's protection level is below its protection mode, so the zero-data-loss guarantee set up for the configuration no longer holds. Check redo transport to the standby, which is unreachable or behind.

**warning**, for 1m

```text
(last_over_time(oracledb.dataguard.protection.degraded[30s]) == 1)
  and on(service.instance.id, obenhub.cluster.name)
(
  max by (service.instance.id, obenhub.cluster.name) (last_over_time(oracledb.database.primary[1m])) == 1
)
```

## OracleFastStartFailoverNotSynchronized

```text
  and on(service.instance.id, obenhub.cluster.name)
```


## OracleStandbyApplyStopped

The managed recovery process of a standby is gone for 3 minutes: redo is received but no longer applied, and the lag will grow. Check V$DATAGUARD_PROCESS and the standby's alert log, then restart apply.

**critical**, for 3m

```text
last_over_time(oracledb.dataguard.apply.running[30s]) == 0
```

## OracleStandbyLag

Transport or apply lag on a standby is above 60 seconds for 2 minutes (lab threshold). Check V$DATAGUARD_STATS and whether redo still arrives (OracleStandbyDataStale) and is applied (OracleStandbyApplyStopped).

**warning**, for 2m

```text
last_over_time(oracledb.dataguard.lag[30s]) > 60
```

## OracleStandbyDataStale

The data the standby's lag is computed from is older than 60 seconds for 2 minutes: redo has stopped arriving even if the lag itself is low. Check redo transport from the primary and the archive destination status there.

**warning**, for 2m

```text
last_over_time(oracledb.dataguard.lag.data_age[30s]) > 60
```

## OracleStandbyLagUnknown

A reporting standby has fewer than the two lag series (apply and transport) for 2 minutes, because V$DATAGUARD_STATS returns NULL, so OracleStandbyLag cannot fire. Check the standby's Data Guard state in V$DATAGUARD_STATS.

**warning**, for 1m

```text
max by (service.instance.id, obenhub.cluster.name, oracledb.database.unique_name) (present_over_time(oracledb.dataguard.apply.running[30s]))
  unless on(obenhub.cluster.name, service.instance.id)
(count by (obenhub.cluster.name, service.instance.id) (present_over_time(oracledb.dataguard.lag[2m])) == 2)
```

## OracleRedoGap

A standby lacks archived logs (V$ARCHIVE_GAP) or the primary reports a destination with a gap, for a minute. Check V$ARCHIVE_GAP on the standby and the archive destination status on the primary.

**warning**, for 1m

```text
(last_over_time(oracledb.dataguard.missing_log.count[30s]) > 0)
  or
(last_over_time(oracledb.archive_dest.gapped[30s]) == 1)
```

## OracleRedoDestinationInvalid

An archive destination is not VALID for a minute: for a remote one the primary can no longer ship redo, for the local one archiving stops. Check V$ARCHIVE_DEST for the error of that destination.

**critical**, for 1m

```text
last_over_time(oracledb.archive_dest.valid[30s]) == 0
```

## OracleListenerUnreachable

A TCP connect to a listener endpoint failed on every check for a minute (tcpcheck receiver; no login, no service lookup). Check that the listener process runs and the port is reachable from the host that runs the tcpcheck receiver.

**critical**, for 1m

```text
last_over_time(tcpcheck.status[30s]) == 0
```

## OracleMonitoringAccountNotOpen

A project monitoring account (C##OBENHUB_*) is not OPEN in DBA_USERS (expired, in grace or locked) for a minute; an expired password stops only new logins, so collection can continue until the next reconnect. Check DBA_USERS for the status and reset the account.

**critical**, for 1m

```text
last_over_time(oracledb.user.open[30s]) == 0
```

## OracleProcessesSaturation

Instance process slots in use are above 85 % of the PROCESSES parameter (critical at 95 %); at the limit a new dedicated server process cannot start. Check V$RESOURCE_LIMIT and which sessions hold the processes.

**warning**, no hold time

```text
WITH (
  r = max by (service.instance.id, obenhub.cluster.name) (oracledb.processes.usage)
    / on(service.instance.id, obenhub.cluster.name)
  max by (service.instance.id, obenhub.cluster.name) (oracledb.processes.limit),
  x = min_over_time(r[90s:30s]),
  n = count_over_time(r[90s:30s])
)
((x > 0.85) unless (x >= 0.95)) and (n >= 3)
```

**critical**, no hold time

```text
WITH (
  r = max by (service.instance.id, obenhub.cluster.name) (oracledb.processes.usage)
    / on(service.instance.id, obenhub.cluster.name)
  max by (service.instance.id, obenhub.cluster.name) (oracledb.processes.limit),
  x = min_over_time(r[90s:30s]),
  n = count_over_time(r[90s:30s])
)
(x >= 0.95) and (n >= 3)
```

## OracleBlockedSessions

A session has waited more than 30 seconds for a lock held by another session (V$SESSION, wait class Application). The alert does not name the blocker; look for it in V$SESSION by blocking_session.

**warning**, no hold time

```text
WITH (
  r = max by (service.instance.id, obenhub.cluster.name) (oracledb.lock.oldest_wait_age),
  x = min_over_time(r[45s:15s]),
  n = count_over_time(r[45s:15s])
)
(x > 30) and (n >= 3)
```
