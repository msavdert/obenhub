# Patroni pack alerts

Generated by `scripts/gen-pack-alerts.py` from `packs/patroni/rules.yml`; do not edit. Each alert is a heading named as the alert, so its anchor is the lowercased name. An alert with two severities has one entry per tier.

## PatroniNoWritablePrimary

No member of the cluster reports patroni_primary 1, so the cluster cannot take writes. Check patronictl list and the DCS.

**critical**, for 90s

```text
WITH (
  last_primary = tlast_over_time((patroni_primary == 1)[1d:15s])
)
sum by (obenhub.cluster.name) (patroni_primary) == 0
  unless on(obenhub.cluster.name)
(
  (
    last_primary
      and on(obenhub.cluster.name, service.instance.id)
    (last_over_time(patroni_primary[1d]) == 1)
      and on(obenhub.cluster.name, service.instance.id)
    (
      obenhub.expected_scrape{service.name="patroni"}
        unless on(obenhub.collector)
      label_replace(present_over_time(otelcol_process_uptime[1m]), "obenhub.collector", "$1", "service.instance.id", "(.+)")
    )
  )
    >= on(obenhub.cluster.name) group_left
  max by (obenhub.cluster.name) (last_primary)
)
```

## PatroniMultiplePrimaries

Two or more members of one cluster report patroni_primary 1 within the last 30 seconds, for a minute: split brain. Check patronictl list and the DCS to see which member holds the leader key, then stop the other.

**critical**, for 60s

```text
count by (obenhub.cluster.name) (
  min by (obenhub.cluster.name, service.instance.id) (
    last_over_time(patroni_primary[30s])
  ) == 1
) > 1
```

## PatroniFailoverHappened

The highest PostgreSQL timeline of the cluster rose compared with the last hour: a switchover or a failover (the metrics cannot tell them apart). It resolves after 3 minutes; patronictl history shows the cause.

**warning**, no hold time

```text
max by (obenhub.cluster.name) (patroni_postgres_timeline)
  > on(obenhub.cluster.name)
max_over_time(max by (obenhub.cluster.name) (patroni_postgres_timeline)[1h:1m] offset 3m)
```

## PatroniReplicaNotEligible

A replica's WAL position is more than 16 MiB (maximum_lag_on_failover) behind the leader's for a minute, so Patroni will not promote it. Check that the replica receives and replays WAL.

**warning**, for 1m

```text
(
  max by (obenhub.cluster.name) (patroni_xlog_location)
    - on(obenhub.cluster.name) group_right()
  (
    (
      clamp_min(patroni_xlog_received_location - patroni_xlog_replayed_location, 0)
        + patroni_xlog_replayed_location
    )
      and on(obenhub.cluster.name, service.instance.id)
    patroni_replica == 1
  )
) > 16777216
```

## PatroniClusterPaused

The cluster has been in maintenance mode (patroni_is_paused 1) for 3 minutes, which disables automatic failover. End it with patronictl resume when the maintenance is done.

**warning**, for 3m

```text
max by (obenhub.cluster.name) (patroni_is_paused) == 1
```

## PatroniPendingRestart

A PostgreSQL parameter changed on the member that needs a restart to take effect, for 2 minutes. patronictl list shows the member flagged; restart it in a maintenance window.

**warning**, for 2m

```text
patroni_pending_restart == 1
```

## PatroniTargetAbsent

Patroni's REST scrape of a member has not succeeded for 2 minutes while that node's PostgreSQL heartbeat is present: Patroni is down on a node whose PostgreSQL still runs, so no failover logic runs there. Check the Patroni service on the node.

**critical**, for 1m

```text
obenhub.expected_scrape{service.name="patroni"}
  unless on(obenhub.cluster.name, service.instance.id)
(max_over_time(up{service.name="patroni"}[2m]) == 1)
  and on(obenhub.cluster.name, service.instance.id)
present_over_time(postgresql.collection.heartbeat[1m])
  and on(obenhub.collector)
label_replace(present_over_time(otelcol_process_uptime[1m]), "obenhub.collector", "$1", "service.instance.id", "(.+)")
```

## PatroniClusterNameMissing

A Patroni scrape carries no obenhub.cluster.name, so the cluster rules count the member nowhere. Fix the resource attribute of the Collector scrape.

**warning**, for 5m

```text
up{service.name="patroni", obenhub.cluster.name=""}
```

## PatroniCollectionIntervalTooLong

Patroni is scraped less often than every 15 s (average spacing above 20 s over 5 minutes), while the rules size their windows for 15 s, so they go quiet or flap. Set the scrape interval back to 15 s.

**warning**, for 10m

```text
max by (obenhub.cluster.name, service.instance.id) (scrape_interval(up{service.name="patroni"}[5m])) > 20
```

## PatroniFailsafeActive

Patroni reports failsafe mode (patroni_failsafe_mode_is_active 1): the DCS is unreachable and the leader keeps running on the failsafe topology. Check the DCS (etcd) and the network to it.

**critical**, for 30s

```text
patroni_failsafe_mode_is_active == 1
```
